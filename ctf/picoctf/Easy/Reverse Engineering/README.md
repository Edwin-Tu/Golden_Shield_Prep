# 逆向工程教學前瞻（Reverse Engineering Roadmap）
## 適合 picoCTF / 初學者 / 題型整理用總覽版

---

## 一、這份文件的目標

這不是單一題解，而是一份 **逆向工程學習前瞻**。

它要幫你建立三件事：

1. **你會學到哪些核心技能**
2. **遇到 Reverse 題時的通用解題流程**
3. **不同題型該如何判斷與下手**

也就是說，這份文件的重點不是只會解某一題，
而是讓你看到題目時，知道自己下一步該做什麼。

---

## 二、什麼是逆向工程？

逆向工程（Reverse Engineering）就是：

> **從已經存在的程式、程式碼、輸出結果、密文或行為，反推出它真正的邏輯。**

在 CTF 裡，逆向工程通常不是要你重寫整個程式，
而是要你回答這些問題：

- 程式真正做了什麼？
- 它如何驗證輸入？
- 它把 flag 藏在哪？
- 有沒有可逆的轉換？
- 有沒有流程能被繞過？
- 有沒有硬編碼的密碼、金鑰或規則？

---

## 三、逆向工程會學到的技能

逆向工程其實不是單一技能，而是一組能力的組合。

### 1. 程式閱讀能力
你會學會：

- 找 `main()` / 入口點
- 看懂輸入從哪裡進來
- 找驗證函式
- 看懂 if / else / loop / return
- 追蹤資料如何流動

這是最基本，也是最重要的能力。

---

### 2. 字串與資料處理能力
很多 Reverse 題都圍繞在：

- 字串切割
- 字元替換
- 編碼 / 解碼
- 拼接 / 重排
- 陣列索引
- ASCII / Unicode 互轉

例如你之前做過的題型就有：

- 把 `picoCTF{...}` 外層去掉再比對
- 把兩個字元打包成一個 Unicode 字元
- 把輸入切段後逐段比較

這代表你要很熟：

- `ord()` / `chr()`
- `substring()`
- `split()`
- slice
- index

這些操作。參考你之前整理的 16-bit 字元打包題與 VaultDoor 題，可看出這兩類就是典型的字串與資料流分析。fileciteturn6file1L1-L83 fileciteturn6file2L1-L109

---

### 3. 位元運算能力
Reverse 題很常用位元運算來混淆資料，例如：

- `<<`
- `>>`
- `&`
- `|`
- `^`

這類運算看起來像加密，其實很多只是：

- 重新排列 bit
- 拆高位 / 低位
- xor 混淆
- 簡單封包

你之前那題把兩個 8-bit 字元合成 1 個 16-bit 字元，就是標準例子。fileciteturn6file1L9-L57

---

### 4. 流程控制與邏輯分析能力
有些 Reverse 題不是藏在公式，而是藏在：

- 程式從哪裡開始跑
- 哪些分支不會被正常執行
- 輸入是否能改變控制流程
- 某些 hidden path 能否被觸發

像你前面做過的歌詞題，重點不是暴力破解，而是：

- flag 其實已經被讀進程式
- 只是正常流程不會印出來
- 透過輸入可改變流程，讓隱藏內容被輸出

這就是典型的 **流程控制型逆向題**。fileciteturn6file0L1-L56

---

### 5. 題型辨識能力
你會慢慢學會：  
看到某些程式特徵，就能快速猜到題目方向。

例如：

- `password.equals("...")`
  - 可能是硬編碼密碼題
- `ord()` / `chr()` + 位移
  - 可能是位元打包 / 字元還原題
- `input` 被拿去 `split(';')`
  - 可能有注入 / 控制流程操控
- `substring()` 一段一段比對
  - 可能是字串拼接 / 分塊還原題
- 明顯的索引重排
  - 可能是 permutation / 重排題
- 大量 xor / rotate / table lookup
  - 可能是簡單自製加密或混淆

這種「看到長相就知道方向」的能力，是逆向工程非常重要的進步指標。

---

### 6. 將程式邏輯轉成自己的語言
真正會解 Reverse 題，不只是能看懂程式碼，
而是能把它翻譯成白話：

- 它先把輸入切掉外殼
- 它拿中間那段去比對
- 它把兩個字元打包成一個字元
- 它讓使用者輸入成為控制語法的一部分

當你能用白話說清楚時，通常就已經理解七八成了。

---

## 四、逆向工程的通用解題流程

這是最重要的一段。  
以後你遇到 Reverse 題，可以先照這個流程走。

---

### Step 1：先判斷題目給了什麼
先確認題目類型是：

- 原始碼（Python / Java / C / JS）
- 編譯後檔案（ELF / EXE / APK）
- 某段密文或輸出
- 一個互動式程式
- 一個驗證器 / vault / checker

先問自己：

- 我現在拿到的是「源碼」還是「結果」？
- 我可以直接讀邏輯，還是需要先觀察行為？

---

### Step 2：找入口點
如果有原始碼，先找：

- `main()`
- `if __name__ == "__main__":`
- `public static void main`
- `reader(...)`
- 程式最後真正呼叫的函式

這一步的目的是搞清楚：

> **程式從哪裡開始跑？**

很多題目答案其實就藏在：
- 起始位置不是你以為的地方
- 某段內容存在，但正常流程不會跑到

像歌詞題就是這種。fileciteturn6file0L57-L90

---

### Step 3：找輸入點
看它從哪裡拿資料：

- `input()`
- `scanner.next()`
- `argv`
- `stdin`
- 檔案讀取
- 網路輸入

然後問：

- 使用者輸入會被怎麼處理？
- 有沒有被切割、轉換、編碼或重排？

這一步能幫你知道真正被驗證的是什麼。

---

### Step 4：找驗證點 / 關鍵比較點
幾乎所有入門 Reverse 題都會有一個關鍵點：

- `if checkPassword(...)`
- `password.equals(...)`
- `if transformed_input == target`
- `return expected == actual`

這裡通常就是最值得看的地方。

先不要急著跑程式，先問：

- 它比的是原始輸入，還是轉換後輸入？
- 是整串比，還是逐段比？
- 目標字串是不是直接寫死？
- 有沒有可以逆推的規則？

VaultDoorTraining 就是最典型的「直接寫死比對字串」。fileciteturn6file2L21-L76

---

### Step 5：判斷是「直接讀答案」還是「需要逆推」
這一步非常重要，因為很多新手會一開始就過度複雜化。

先分流：

#### 類型 A：答案其實直接在程式裡
例如：
- 硬編碼密碼
- 明顯的 flag 字串
- 字串常數直接出現
- 檢查函式直接 `equals("...")`

這種題目重點在閱讀，不在計算。

#### 類型 B：有轉換，但可逆
例如：
- 位移、xor、重排、base64、自製打包
- 逐段 substring 比對
- 陣列對應

這種題目要做的是「把規則倒過來」。

#### 類型 C：有流程操控點
例如：
- 可透過輸入影響 return / jump / next state
- 某段 hidden logic 正常不執行
- 可利用注入或邏輯漏洞讓 flag 被印出

歌詞題屬於這類。fileciteturn6file0L57-L109

---

### Step 6：把程式轉成白話邏輯
這一步是解題加速器。

把它整理成：

1. 程式先做什麼
2. 接著做什麼
3. 最後比較什麼
4. 哪一步最可疑
5. 我能不能把規則倒回來

例如：

- 它先讀使用者輸入
- 去掉 `picoCTF{` 和 `}`
- 再拿中間字串與固定密碼比較

這樣你馬上就知道怎麼解。fileciteturn6file2L29-L76

---

### Step 7：驗證你的推論
最後再用：

- 手算
- 小腳本
- 本地執行
- 加上 `print`
- 用 Python 重寫驗證函式

去確認你的想法正不正確。

Reverse 很多時候不是一口氣看懂，
而是：

> 先猜一個規則 → 寫小程式驗證 → 修正 → 得到答案

---

## 五、逆向工程的通用判斷標準

遇到題目時，你可以先用這幾條快速判斷。

---

### 判斷 1：有沒有直接常數？
先搜：

- `picoCTF`
- `flag`
- `password`
- `equals`
- `compare`
- `return`
- `secret`
- `key`

如果有固定字串，先懷疑是不是答案就在裡面。

---

### 判斷 2：輸入有沒有被轉換？
常見轉換包括：

- `substring`
- `replace`
- `split`
- `reverse`
- `sort`
- `ord`
- `chr`
- `xor`
- `base64`
- `hex`

有轉換就代表：
> 真正比對的不是原始輸入，而是轉換後結果。

---

### 判斷 3：轉換是不可逆還是可逆？
如果只是：

- xor
- rotate
- shift
- 重排
- 拼接
- table lookup

通常都是可逆的。

如果是：

- 真正雜湊（SHA-256 / MD5）
- 隨機值參與
- 伺服器端秘密未知

就不一定能直接反推。

但 picoCTF 入門 Reverse 題很多都還是可逆或半可逆。

---

### 判斷 4：有沒有明顯的 hidden path？
問自己：

- flag 是不是早就存在記憶體 / 字串裡？
- 只是平常流程不會到？
- 某個分支能不能被強制觸發？
- 使用者輸入會不會影響流程？

這是很多「看起來不像逆向，其實是邏輯逆向」的題目重點。fileciteturn6file0L7-L18

---

### 判斷 5：題目是在考閱讀，還是考運算？
如果程式碼短、邏輯明確、字串很多，
通常考的是閱讀。

如果程式碼裡有：
- 多層位元運算
- 陣列映射
- 大量索引重排
- 字元表
- 自製 encode

那比較可能考運算與逆推。

---

## 六、常見逆向題型總整理

---

### 1. 硬編碼密碼題
特徵：

- `equals("固定字串")`
- 直接比對常數
- flag / password 明顯存在

做法：

- 找驗證函式
- 找固定字串
- 看輸入是否有前後處理
- 補回正確格式

典型例子：VaultDoorTraining。fileciteturn6file2L19-L76

---

### 2. 字串切割 / 拼接題
特徵：

- `substring`
- `split`
- 多段比較
- 一段一段檢查

做法：

- 列出每一段規則
- 照索引順序拼回去
- 注意是不是有順序重排

---

### 3. 編碼 / 位元打包題
特徵：

- `ord` / `chr`
- `<<` / `>>`
- `& 0xff`
- 看似亂碼的 Unicode 字串

做法：

- 先看是怎麼打包的
- 再逆向拆回高位 / 低位
- 寫短腳本驗證

典型例子：16-bit 打包字元題。fileciteturn6file1L9-L83

---

### 4. 流程控制 / 邏輯操控題
特徵：

- 程式中有 hidden branch
- 有 `RETURN` / `JUMP` / label 之類設計
- 使用者輸入會被程式重新當成語法

做法：

- 先確認 flag 是否早已在程式資料中
- 再看如何改變流程讓它被印出
- 把使用者輸入視為 attack surface

典型例子：Flag Hunters。fileciteturn6file0L57-L109

---

### 5. 索引重排 / permutation 題
特徵：

- `password[3] == 'x'`
- `arr[i] = input[j]`
- 很多固定索引對應

做法：

- 建表
- 把每個位置填回去
- 最後拼成完整字串

---

### 6. 簡單 xor / 代換題
特徵：

- `^`
- 自製字元映射
- 每個字元做同樣處理

做法：

- 找 key
- 看是不是單位元組 xor
- 直接反向套回去

---

## 七、初學者最常犯的錯

### 1. 還沒看懂就急著跑工具
很多入門 Reverse 題其實直接看就能解。  
不要一開始就想：

- IDA
- Ghidra
- 動態除錯
- 爆破

先看程式本身在做什麼。

---

### 2. 只看表面輸入，不看中間轉換
像 VaultDoor 題，如果你沒注意 `substring()`，
就會誤以為整串 `picoCTF{...}` 被直接拿去比。fileciteturn6file2L31-L63

---

### 3. 把可逆題誤認成真正加密
很多題目看起來很像加密，
其實只是：

- 重排
- xor
- 位元拼接
- 字元打包

這些都不是不可逆。

---

### 4. 沒有把規則寫成小腳本驗證
有時候你已經差不多看懂了，
但還卡在「不確定」。

這時不要硬想，直接寫 5~10 行 Python 驗證最快。

---

### 5. 忘記題目真正考的是哪一層
不是每一題都要逆組譯。  
很多 picoCTF easy Reverse 題考的是：

- 程式閱讀
- 邏輯還原
- 字串處理
- 控制流程理解

## 九、建議的練習順序

如果你要有系統地學，建議這樣練：

### 第一階段：原始碼閱讀題
先練：
- 硬編碼密碼
- substring / split / equals
- 明顯字串比對

目標：
- 能快速找入口、輸入、比較點

---

### 第二階段：簡單可逆轉換題
再練：
- ord / chr
- xor
- shift
- base64 / hex
- 字串重排

目標：
- 能把轉換倒回去

---

### 第三階段：流程控制題
再來練：
- hidden branch
- 邏輯操控
- 狀態跳轉
- 可注入的流程語法

目標：
- 不只看資料，也會看流程

---

### 第四階段：二進位逆向
最後再進到：
- ELF / EXE
- 組語
- 反編譯
- debugger

這樣學會比較扎實，不容易一開始就被工具壓垮。

## 十、逆向工程的通用口訣

你可以記這句：

> **先找入口，再找輸入；先找比較，再看轉換；先判斷是否可逆，再決定要不要寫腳本。**

也可以拆成六問：

1. 程式從哪開始？
2. 輸入從哪進來？
3. 哪裡在驗證？
4. 驗證前做了什麼轉換？
5. 這個轉換能不能倒回去？
6. flag 是被藏起來，還是其實已經在程式裡？

---

## 十一、總結

逆向工程在初學階段，最重要的不是工具，
而是這三件事：

### 1. 會拆程式流程
知道入口、輸入、比較點在哪。

### 2. 會看資料怎麼被轉換
知道字串、位元、索引、編碼是怎麼變化的。

### 3. 會判斷題型
知道這題是：
- 直接讀答案
- 可逆還原
- 邏輯操控
- 還是真的要上更重的工具

你前面整理過的幾題，其實就剛好覆蓋了逆向入門很重要的三大方向：

- **直接從原始碼讀答案**（VaultDoorTraining）fileciteturn6file2L1-L109
- **從位元 / 字元打包規則倒推**（16-bit 字元題）fileciteturn6file1L1-L83
- **透過輸入改變流程觸發隱藏內容**（Flag Hunters）fileciteturn6file0L1-L56

這三類學會後，你對 picoCTF 的入門 Reverse 題會有非常清楚的地圖。

## 十二、一頁式超精簡版流程

```text
1. 看題目給的是源碼、執行檔，還是密文
2. 找入口點（main / 呼叫位置）
3. 找輸入點（input / scanner / argv）
4. 找驗證點（equals / compare / if）
5. 看輸入有沒有被轉換（substring / xor / ord / chr / split）
6. 判斷是：
   - 直接可讀
   - 可逆轉換
   - 流程操控
7. 寫小腳本驗證
8. 還原 flag
```

## 十三、給初學者的一句建議

> **Reverse 不是先學會用很重的工具，而是先學會把程式「翻譯成人話」。**

當你能用自己的話說清楚一題在幹嘛，
你就已經走在正確的路上了。
